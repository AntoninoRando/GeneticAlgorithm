1. Initialisation: ramped half-and-half

initialize(populationSize, crossoverRate, mutationRate, elitismCount, maxDepth, hoistRate, …) stores the parameters and builds the first population with TreeBuilder::rampedHalfAndHalf(count, minDepth, maxDepth):

for i in 0 .. count-1:
    depth = minDepth + (i mod (maxDepth - minDepth + 1))
    tree  = grow(depth) if i is even else full(depth)
  • full(d): every node above depth \(d\) is an operator, so every leaf sits at depth exactly \(d\).
  • grow(d): an operator or a terminal at each node. This version is biased: with 3 or more levels left it always picks an operator, and below that it picks a terminal with probability 0.55. The bias keeps small grow trees, used in subtree mutation, from collapsing into a single leaf.
  • An operator is binary with probability 0.70, unary otherwise, then chosen uniformly within its arity.
  • The depth range is 2 to initialMaxDepth, which defaults to the cap maxDepth.
Literature

Ramped half-and-half gives "a wide variety of different sizes and shapes" (koza1994gp §4) and is used by every GP-for-scheduling paper we follow (mtgp_multicloud §4.1, zhang2025mtgper §3.2.1, gp_fog §VI-A.2). The papers start below the depth cap (2–7 with cap 8; 2–6 with cap 8; 1–3 with cap 7; Koza 6 with cap 17), so crossover has room to grow trees. Here that is the opt-in --initial-max-depth.

Quirk: grow and full can get locked to alternate depths

When the number of depths in the ramp is even (cap 7 gives depths 2–7, six values), \(i \bmod 6\) and \(i \bmod 2\) have the same parity. Every grow tree then gets depth 2, 4 or 6, and every full tree 3, 5 or 7. Koza's method uses both methods at every depth. With cap 4 (depths 2–4, three values), the setting of the experiments, this does not happen. See Known quirks.

2. Sort and elitism

solveNextGeneration() starts by sorting the population ascending by fitness with stable_sort, so the best is last and ties keep a fixed order. Then it copies the elitismCount (2) best individuals unchanged into slots 0 and 1 of the next population.

Elitism guarantees that the best trees survive. It does not guarantee that the best fitness value never decreases. Response time and energy are re-normalised against each new population, so an elite with unchanged raw objectives can get a lower fitness next generation. The convergence check in main.py (10 generations without a new best fitness in the current world) is therefore a heuristic stopping signal, not a strict plateau test. The opt-in fixed-bound fitness removes this: an elite then scores exactly the same in the next generation, so the best fitness cannot decrease while the worlds stay the same.

3. Tournament selection

tournamentSelectRng(pop, k, rng):
    best = random index
    repeat k-1 times: cand = random index;  if fitness[cand] > fitness[best]: best = cand
    return pop[best]

The \(k\) (default 5) draws are uniform with replacement. Each offspring pair draws two parents independently.

Literature

Koza originally used fitness-proportionate selection. The scheduling papers all use tournaments (mtgp_multicloud §4.1, zhang2025mtgper §3.2.1, gp_fog §VI-A.4), with \(k = 7\) or \(k = 2\). Tournament selection depends only on the ranking of fitness values, not their scale. That suits a fitness that is re-normalised every generation. The exact selection probabilities are derived on the theory page.

4. Crossover

With probability crossoverRate (0.80) the two parents go through TreeOperators::crossover; otherwise the children start as plain copies.

  1. Copy both parents.
  2. Pick a node in each copy, uniformly over all nodes by default, and swap the two subtrees in place.
  3. If a child breaks the depth cap or the size cap, it is replaced by a copy of its parent, not by a new random tree.
Literature

Subtree crossover is the standard GP operator (koza1994gp §3; mtgp_multicloud Fig. 3a). Reverting an oversized child to its parent plays the role of Koza's depth limit on crossover offspring. Koza chooses an internal (operator) node as crossover point 90% of the time, because in a binary tree about half the nodes are leaves, and a leaf-for-leaf swap is just a point mutation. That bias is the opt-in --internal-crossover-bias 0.9.

5. Mutation and simplification

TreeOperators::mutate(tree, mutationRate) walks the tree. At each node, with probability mutationRate (0.08):

NodeEffectSource
terminalredraw the terminal indexpoint mutation, project addition
operator, 10%replace the whole subtree with a fresh grow(3) tree and stop theresubtree mutation (mtgp_multicloud Fig. 3b, gp_fog §VI-A.5)
operator, 90%swap for a different operator of the same arity, keep the children, keep walkingpoint mutation, project addition

Then the tree is simplified (ExprNode::simplifyInPlace). Six rules are applied bottom-up, and every one of them is exact under the protected semantics: the score never changes for any (job, satellite) pair.

$$\text{NEG}(\text{NEG}(x)) \to x \quad \text{ABS}(\text{ABS}(x)) \to \text{ABS}(x) \quad \text{ABS}(\text{NEG}(x)) \to \text{ABS}(x)$$ $$\text{MAX}(x,x) \to x \quad \text{MIN}(x,x) \to x \quad \text{SUB}(x,x) \to 0$$

Two tempting rules were deliberately removed: \(\text{DIV}(x,x) \to 1\) is wrong when \(x \approx 0\), because protected division returns 0. \(\text{INV}(\text{INV}(x)) \to x\) is wrong when \(|x| \le 10^{-9}\) or \(|x| \ge 10^{9}\). If the result still breaks a cap, the mutation is undone.

Rates are per node, not per individual

In the papers, crossover, mutation and reproduction are alternatives chosen once per offspring (for example 0.80 / 0.15 / 0.05). Here crossover is followed by mutation, so an offspring can get both. A tree with \(n\) nodes receives on average about \(0.08\,n\) point mutations (a bit fewer, because subtree replacement stops the walk). For a 15-node tree that is about 1.2.

6. Hoist and the size caps

With probability hoistRate (0.05) per child, hoist replaces the whole tree with one of its non-root subtrees, chosen uniformly. This is a project addition against bloat; the papers rely on the depth cap alone.

Every offspring must satisfy \(\text{depth} \le D_{\max}\) and \(\text{size} \le 2^{D_{\max}+1}\). Depth counts edges, so a lone terminal has depth 0.

Two quick consequences, worked out on the theory page
  • Because about half the nodes of a tree are leaves, a hoist lands on a single terminal more than half of the time. That is why a hoist rate of 0.2 collapsed trees to size 1.2 in the experiments.
  • With arity at most 2, a tree of depth \(\le D\) has at most \(2^{D+1} - 1\) nodes, so the size cap can never be the one that fails. See theory.

8. Parallelism and reproducibility

Offspring are produced in an OpenMP loop over pairs. Pair \(p\) writes only to slots \(2p\) and \(2p+1\) of a pre-sized vector, so threads never write to the same place. Each pair gets its own random-number generator:

baseSeed = master_rng()                       # drawn once per generation, serially
pair p:  rng_p = mt19937(seed_seq{baseSeed, p})

Because the streams belong to pairs, not threads, a run with --seed gives bit-identical results whatever the number of threads or the OpenMP schedule. Independent, reproducible runs are what make the 20-seed statistical comparisons in the thesis valid. Fitness evaluation is a second parallel loop, over individuals.
